# Notes

## play

- `Env{ZomboidDir, OpenURL, Running}` makes everything injectable for tests; package funcs `ListSaves/ListServers/Launch` use `Default()` (real ~/Zomboid, real opener, real process check).
- Saves: every dir under `Saves/` except `Multiplayer` (and mode names with spaces, which the Lua side can't parse) counts as a mode; worlds sorted newest first by dir mtime.
- Servers: `db/ServerListSteam.db` opened as `file:...?mode=ro` with modernc.org/sqlite (no CGO). Only `id,name,ip,port` and `account.username,isSavePassword` are selected; password columns are never read. One `Server` per row with its `Accounts`.
- Launch writes all three triggers every time so stale ones can't win: save/latest -> `AutoLoadSave.txt` + empty `AutoConnect.txt`; server -> `AutoConnect.txt` "<ip> <port> [account]" + empty `AutoLoadSave.txt`; always `AutoStart.txt` "1". The Lua mod checks AutoConnect first, so clearing it matters.
- Then opens `steam://rungameid/108600` (xdg-open / open / `rundll32 url.dll,FileProtocolHandler`, falling back to `cmd /c start "" url`). No +connect/+password args ever (Steam puts them before the launch options, they reach the JVM).
- Running check: Linux scans /proc/*/comm for `ProjectZomboid*` (comm is truncated to `ProjectZomboid6`) and java processes whose cmdline has `zombie.gameclient.main`; falls back to `pgrep -x ProjectZomboid6` where /proc is missing. Windows: Toolhelp snapshot for `projectzomboid*.exe`; if a java/javaw exists, PowerShell CIM reads command lines and matches `projectzomboid` / `zombie.gameclient.main`, skipping `zombie.network.gameserver` so a dedicated server on the same box doesn't block playing.
- From an AppImage, xdg-open gets an environment with AppImage vars (LD_LIBRARY_PATH, APPDIR, ...) stripped so the browser/Steam don't load bundled libs.
- Account names with spaces are refused (Lua pattern is `%S*`).

## update

- `update.Repo` default `OWNER/pzlauncher`; set with `-ldflags "-X github.com/katachinosekai/pzlauncher/internal/update.Repo=owner/repo"`. `Latest()` refuses the placeholder.
- `Latest()` reads `/repos/<repo>/releases/latest` (no token, 60 req/h limit) and then `manifest.json` from the release assets. Pack asset = first `PZ-Fixes.zip` / `PZ-Fixes-*.zip`.
- `Download` streams to a temp file next to the destination while hashing; a missing/invalid hash in the manifest is an error, mismatch returns `ErrChecksum` and deletes the temp file.
- `FetchPack` -> cache `os.UserCacheDir()/PZLauncher/packs/pack-<version>`; zip deleted after extraction. Returns `PackRoot(dir)`: if the zip has exactly one top-level folder, that folder is returned instead of the extraction root. The installer gets this path as `PackDir`.
- `Extract` validates every entry first (rejects `..`, absolute, backslash-escapes, drive letters/colons, symlinks, >4 GiB total) and only then writes, so a bad zip leaves nothing behind.
- State: `os.UserConfigDir()/PZLauncher/state.json` `{"pack_version","installed_at"}`, written atomically. GUI records it only after a successful non-dry-run install.
- Versions compare as dotted numbers, leading `v` and `-suffix`/`+meta` ignored. `Newer(latest, "")` is true (nothing installed). `LauncherOutdated` is false for `dev` builds so local builds never self-update.
- Self-update: Linux only from an AppImage (`$APPIMAGE` is replaced by rename, the running FUSE mount keeps the old inode). Windows: `exe -> exe.old`, `exe.new -> exe`, rolls back if the second rename fails; `CleanupOld()` at startup retries deleting `.old` for 15 s while the old process exits. `Restart` starts the new binary with the same args; the GUI then quits.

## install

Port of `Zomboid-B42.22-Fixes/scripts/install.ps1` (727 lines, state of 2026-11-19) to `internal/install`. Installs from an extracted PZ-Fixes pack directory (`Options.PackDir`).

### API

- `Run(ctx, Options) (Report, error)` runs every step in order and stops at the first error. For a progress UI: `in, _ := New(opts)`, loop over `in.Steps()` (`ID`, `Title`, `Run(ctx)`), then `in.Finish(err)` for the report and the closing log lines.
- Every root is injectable: `SteamRoot`, `ZomboidDir`, `ZombieBuddyHome`, `BackupRoot` (default PackDir, like `$Here\bk-*`), `LogDir` (default `PackDir/logs`, fallback `$TMP/PZ-Fixes-logs`; `NoLogFile` turns it off), `GOOS` (decides Windows vs Linux behaviour; tests run both on Linux), `System` (process check, open URL, close/start Steam), `CollectionAPI` + `HTTPClient` (Steam GetCollectionDetails), `PollInterval` (10 s like the ps1), `SteamPollInterval` (2 s), `Now`.
- `NoWait` = the ps1's hidden `-HarnessNoWait`: no Viewpoint/collection waiting, Steam is never closed for the launch options (files are still edited, like the harness).
- `DryRun` (dropped from the ps1 on 11-16, re-added here because the launcher wants a preview): every step runs and logs what it would change (`Report.Changes`), but nothing is written, no backup folder is made and Steam is never touched or opened. Implies NoWait.
- Waiting (Viewpoint re-download, collection "Subscribe to all") is a polling loop inside the `viewpoint` / `collection` steps that calls `Options.OnWait(WaitStatus{What, Installed, Total, Missing, Done})` every poll and stops on ctx cancel (the ps1's Ctrl+C). `Installer.WaitCollection(ctx, ids)` is exported on its own too.
- `FatalError` = the ps1's `Fatal` (game running, no library, no Workshop folder, Steam did not close for the Viewpoint swap). Report has `Changes`, `Warnings`, `BackupDir`, `LogFile`, `Failed`.
- Pure text edits are exported and table-tested: `SetXmx`, `AddJVMFlags`, `HasZBBatchAgent`/`RemoveZBBatchAgent`, `AddVMArg`, `PlaceShim`, `EnableMods`, `LaunchEditWindows`, `LaunchScanLinux`, `ParseApprovals`/`MergeApprovals`, `BumpVersionMax`, `RemoveAcfItem`, `NightlyFromModInfo`.

### Regex/case details

PowerShell `-match`/`-replace`/`-eq` are case-insensitive, `[regex]::Replace` and `-ceq` are not. Kept: `-Xmx` detection/replace case-sensitive (the ps1 would back up and rewrite unchanged text for a lower-case `-xmx`; here it is just inserted-or-replaced consistently), flag presence check case-insensitive, `-javaagent:ZBBatch.jar` removal case-insensitive, shim lines case-insensitive, approvals id/hash compare case-insensitive. BOMs are stripped on read (ReadAllText/Get-Content did that); everything is written UTF-8 without BOM like the ps1.

### approvals merge

`mod_approvals.json` is merged at the raw-JSON level: top-level keys keep their order, existing `mods` entries are copied byte-for-byte (so 64-bit `author_id`/`workshop_id` never go through float64), new entries are `{"id","jar_hash","decision":true}`; output is 2-space indented (the ps1's ConvertTo-Json produced its own layout). Bad JSON is an error (the ps1 would die in ConvertFrom-Json too).

### Windows vs Linux

- Game dir: Windows `<lib>/steamapps/common/ProjectZomboid`, Linux `.../ProjectZomboid/projectzomboid` (from `paths.GameDir`); `ProjectZomboid64.json`, `ZBBatch.jar` and `ZombieBuddy.jar` all live there.
- Process names: Windows Toolhelp snapshot, `ProjectZomboid64.exe`/`steam.exe`; Linux `/proc/*/comm` (names cut to 15 chars, so `ProjectZomboid6`), `steam`.
- Closing Steam: Windows `steam://exit` via `rundll32 url.dll,FileProtocolHandler`; Linux `steam -shutdown` (falls back to `flatpak run com.valvesoftware.Steam -shutdown` when there is no `steam` on PATH). Both then poll until the process is gone (30 x 2 s for the Viewpoint swap, 45 x 2 s for launch options). Restart: Windows `<steamRoot>/steam.exe`, Linux `steam` in a new session. URLs: Linux `xdg-open`.
- ZBBatch switch-on:
  - Windows (as the ps1): plain `-javaagent:ZBBatch.jar` in ProjectZomboid64.json kills the game at launch with no log (instrument.dll can't load until zbNative fixes the DLL path), so it is removed from the json and inserted into Steam's LaunchOptions right after `-agentlib:zbNative...` (`-agentlib:zbNative -javaagent:ZBBatch.jar --`). Needs Steam closed (Steam rewrites localconfig.vdf on exit); restarted afterwards if it was running. No zbNative loader -> warning, left off.
  - Linux: the DLL problem doesn't exist and ZombieBuddy is loaded as a plain agent (`gamemoderun %command% -javaagent:ZombieBuddy.jar -- -`). ZBBatch goes into the json instead, appended as the last `vmArgs` element (`AddVMArg`, keeps the file's indentation, validated). That is exactly the user's own working Linux setup (checked 2026-11-19: json ends with `"-javaagent:ZBBatch.jar"`, launch options only carry ZombieBuddy) and needs no Steam restart, so on Linux localconfig.vdf is only read, never written. It is switched on only when a ZombieBuddy loader is found (`-javaagent:ZombieBuddy.jar` or `-agentlib:zbNative` in a 108600 LaunchOptions, or ZombieBuddy in the json); if the launch options already contain `-javaagent:ZBBatch.jar` the json is left alone (no double load). Steam closing on Linux is therefore only used by the Viewpoint nightly swap.

### Local mods (AutoLoadSave)

`LocalMods` copies every directory in `<pack>/localmods/` (and the ps1's `<pack>/payload/localmods/`) to `Zomboid/mods/<dir>` (unchanged tree = skipped; changed = old copy backed up to `Zomboid-mods/` and replaced). Ids listed one per line in `localmods/enable.txt` (`#` comments allowed; it is a file, so it is never copied as a mod) are added to the end of the `mods { }` block of `Zomboid/mods/default.txt` in the `ModList` step, after the shim, copying the existing `mod = ` / `mod = \` style. Intended for the trimmed AutoLoadSave helper (only the AutoLoadSave.txt / AutoConnect.txt / AutoStart.txt triggers, built from `zomboid-fastload/mods/AutoLoadSave`), shipped as `localmods/AutoLoadSave/` + `localmods/enable.txt` containing `AutoLoadSave`. The mod itself is not built here. Note the settings snapshot `mods/default.txt` is copied over the user's list each run; the enable step re-adds the ids afterwards and the settings step treats "pack copy + shim + enabled ids" as up to date.

## checks

Pre-launch checks in `internal/play` (`check.go`, `servercheck.go`, `mods.go`, `classfile.go`, `gameversion.go`, `rules.go`) that mirror the game (B42.22 jar + Lua, read 2026-11-19). `Env` got `GameDir`/`WorkshopDir` (filled by `Default()` from `paths`). `env.NewChecker()` reads the game info once (cached per jar path/size/mtime), scans all installed mods (~30 ms for ~380 mods) and `mods/default.txt`; then `CheckSave(save)`, `CheckLatest(saves)` (checks `saves[0]`, the newest), `CheckServer(server, *account, status)`. Package funcs `CheckSave(s, env)` / `CheckServer(srv, acct, st, env)` build a fresh checker. Result = `[]Issue{Severity, Text}`: `SevError` blocks Launch, `SevWarning` asks "continue anyway", `SevInfo` is shown only.

### Game info from the jar

No JDK, so `classfile.go` parses class files itself (constant pool, fields, method Code, opcode lengths incl. switch/wide). World version: `IsoWorld.getWorldVersion()` body `sipush N; ireturn` (fallback: `WorldVersion` ConstantValue) = 251. Game version: in `Core.<clinit>` the `new GameVersion(int, int, String)` right before `putstatic Core.gameVersion` = 42, 22, "" -> "42.22" (`GameVersion` formats `%d.%d%s`; the constructor before it for another field is skipped).

### Single player (LoadGameScreen.disableBtn ~890, MainScreen.checkSaveFile ~1046)

- `map_ver.bin` like `LuaManager$GlobalObject.getSaveInfo`: big-endian int world version, then `GameWindow.ReadString` = big-endian int char count (>65536 = corrupt) + that many UTF-16BE chars (`readChar`). Map name "DEFAULT" becomes "Muldraugh, KY". Real save 2026-11-17_18-54-25: 251 + 602 chars, 21 `;`-separated maps (RUSA spawns, vehicle_interior_arcadia_realusa, Real USA Country).
- Errors in disableBtn order: no world version or map name (save missing/corrupt); world version > game's; world version <= 200; map missing; Apocalypse dead player.
- Maps (`LoadGameScreen.checkMapsAvailable` -> `MapGroups.createGroups(activeMods, true, true)` + `getAllMapsInOrder`): each `;` part of the map name (not trimmed, like LoadGameScreen; MainScreen trims) must be a folder with `map.info` in the game's `media/maps` (plus `challengemaps/<x>`) or in `<commonDir>/media/maps` / `<versionDir>/media/maps` of an active mod that is *available* (`getAvailableModDetails`); a mod's own `challengemaps` folder is skipped. Active mods = save `mods.txt`, or `mods/default.txt` when the save has none.
- Apocalypse: the check is `gameMode == "A Really CD DA"` (mode folder name) and `PlayerDBHelper.isPlayerAlive(dir, 1)`: `map_p.bin` exists -> alive; else `players.db` (or the old `vehicles.db` when players.db is missing) `SELECT isDead FROM localPlayers WHERE id=1`, no row = dead. DB opened `mode=ro&immutable=1` (the real save had a `players.db-journal`). `ListSaves` skips mode names with spaces, so such a save never shows up in the launcher anyway.
- Warnings (`MainScreen.getMissingMods` ~1032): every `mods.txt` id with no mod (`getModInfoByID` = `ChooseGameInfo.getModDetails`) or not `isAvailable()`.
- `mods.txt` / `default.txt` (`ActiveModsFile.fromString`): `/* */` comments stripped, `VERSION` must be exactly 1 (else no mods), `mods { mod = X, }` (key case-insensitive, value trimmed, backslashes removed, blank skipped), `maps { map = X, }`.
- Launcher requirement: `AutoLoadSave` must be in `mods/default.txt` (blocking for every target, servers too, since AutoConnect also lives in that mod) and must itself be installed + available (its `require=\ZombieBuddy` included).

### Mod resolution (ZomboidFileSystem / ChooseGameInfo)

- Folder order `workshop,steam,mods`: `~/Zomboid/Workshop/*/Contents/mods/*` (staged uploads), `<lib>/steamapps/workshop/content/108600/*/mods/*`, `~/Zomboid/mods/*`; `examplemod` skipped; first folder with an id wins. The game asks Steam for installed items; here every item folder on disk counts (unsubscribed leftovers too).
- A mod folder counts only if `<mod>/common/mod.info` or `<mod>/<versionDir>/mod.info` exists. No root `mod.info` fallback in B42 (B41-only mods are "not installed"). versionDir (`getModVersionDirName`): the entry whose `getGameVersionIntFromName` (`a` -> a*1000, `a.b[.c]` -> a*1000+min(b,999)) is the highest in [42000, game int], default `"42.0"`. `mod.info` read from versionDir, else common.
- `readModInfoAux` line rules kept in order: `name=`/`poster=`/`description=`/`require=`/... use `contains`, `id=`/`versionMin=`/`versionMax=` use `startsWith` on the untrimmed line; id default `undefined_id`; an unparsable versionMin/Max drops the whole mod. `require=` = line with key and `\` removed, Java `split(",")` (trailing empties dropped, so `\A,\B,` is fine; an empty `require=` gives `[""]`, which makes the mod unavailable in the game too).
- `isAvailable`: `versionMin.getInt() > game.getInt()` or `versionMax.getInt() < game.getInt()` -> no (getInt = major*1000+minor, suffix ignored), then every required mod recursively the same (cycles stop).

### Servers

- `QueryServer` now also reads A2S_INFO visibility (password) and keywords (EDF 0x80 port, 0x10 steamid, 0x40 sourcetv, 0x20 keywords) and then A2S_RULES (`0x56` + challenge, `A` reply retried with the challenge, up to 3 times) on the same port. Split replies `0xFFFFFFFE` (Source layout: id, total, number, size; reassembled in any order; compressed id bit = error). Real server: single 226-byte packet, 8 rules.
- Server side (`GameServer.setupSteamGameServer`): `version` = `Core.getVersionNumber()` (gameVersion string), `open`/`public`/`pvp` 0/1, `modCount`, `mods` = ids joined by `;` cut by the game to whole ids <= 128 chars, Steam then cuts the value to 127 (real: ends with `ETO_`) and names it `mods:1/1`. `ServerModsPrefix` joins `mods`/`mods:i/n` and drops the last id when a value is >= 127 chars. Keywords carry `hidden;modded;pvp;VERSION:42.22` and `closed` when not open (`steamGetInternetServerDetails`), used as fallback when rules are missing.
- Version: the server's `LoginPacket.processServer` compares the client's `getGameAndBuildVersion()` ("42.22.2", build constant 2) with its own by exact `String.equals` and replies `ClientVersionMismatch`. Rules only show the `GameVersion` part, so the check is exact equality of `version` with the installed game version string (suffix included). Build number cannot be compared.
- Errors: offline, full (players >= max), version mismatch, plus the AutoLoadSave requirement. Warnings: only ping answers (no A2S), no saved account / account password not saved (auto-join stops), password required (visibility 1) but `server.serverPassword` empty in ServerListSteam.db (`ListServers` selects only `length(serverPassword) > 0`, never the value), closed (`open=0`) and no saved account. Info: mod count, the visible prefix ids not installed locally ("downloaded on join"), server version.

- `ProjectZomboid64.json`: own span scanner over the `vmArgs` array; edits replace, insert or delete single string tokens, so the rest of the file (other entries, order, indent, CRLF, BOM) stays byte-identical. Empty array falls back to `install.AddVMArg`. Result must be valid JSON or nothing is written.
  - `-Xmx` is written as `-Xmx<MB>m`; an equal value in another unit (`-Xmx8g`) is left alone. Missing `-Xmx` is inserted first in the array (like `install.SetXmx`).
  - Flag list is `install.JVMFlags` (edits.go has no GC detection: the installer adds all six regardless of GC). The tab only shows the GC (`DetectGC`). Turning a flag on inserts it after `-Xmx` / the previous pack flag present (installer order); a `-XX:-Foo` entry is flipped in place. Off removes every exact match.
  - `-XX:SoftMaxHeapSize` matches any value. Kept below Xmx: if >= Xmx it becomes `DefaultSoftMaxMB` (6g, or Xmx-2g from 4g up, or 3/4 Xmx) with a note.
  - `-XX:+UnlockExperimentalVMOptions` is kept on while `-XX:ShenandoahUncommitDelay=30000` is on (not verified whether that flag is still experimental in the bundled JDK 25; kept on to be safe).
  - Memory choices: 2 GB to (RAM rounded to GB) - 2, 1 GB steps; a non-whole current value is offered as "current: ...". RAM from `/proc/meminfo` or `GlobalMemoryStatusEx` (lazy kernel32 proc; x/sys v0.50 has no wrapper).
- `settings.json` in `<UserConfigDir>/PZLauncher`: `{xmxMB, flags, softMaxMB, debug}`. Every successful memory save (also no-op saves) remembers the state read back from the file; "Re-apply my memory settings" writes it again after a Steam update. `debug` is the "Launch with debug mode" checkbox, saved on toggle; `gamecfg.DebugEnabled()` reads it for the Play tab (trigger file is written there, not here).
- `options.ini` (`~/Zomboid`): kept as raw byte lines with their own endings; only the value bytes of existing keys are replaced, missing keys are never added (their controls are hidden or skipped). Values compared case-insensitively / numerically so an unchanged form writes nothing. Keys, confirmed from the real file and `MainOptions.lua` (B42.22):
  - display mode: `fullScreen` / `borderless` (Lua: fullscreen if `isFullScreen`, else borderless if `getOptionBorderlessWindow`, else windowed); the tab writes both.
  - `width`, `height` (640-16384 / 480-16384), `vsync`.
  - `frameRate` (Lua list 244 240 165 144 120 95 90 75 60 55 45 30 24) and `uncappedFPS` ("Uncapped" only offered when that key exists; in Lua it is behind `SystemDisabler.getUncappedFPS()`, unsure how the game treats it otherwise).
  - `fontSize` 1-6 = 16/19/26/33/38 px / scale with window height.
  - volumes 0-10: `soundVolume`, `musicVolume`, `jumpScareVolume`, `vehicleEngineVolume`. `ambientVolume` and voice volumes exist in the file but not in MainOptions, so not exposed.

## backups

`internal/savebak` + `cmd/pzlauncher/backupspanel.go`. No separate tab (user decision 2026-11-19): backups are shown as details of a save in the Play tab.

### Layout and naming

- Backup root: `backups.json` `root`, default `os.UserConfigDir()/PZLauncher/save-backups`. A root inside `<Zomboid>/Saves` is refused (`CheckRoot`). Changing the root does not move existing backups.
- File: `<root>/<Mode>/<World>/<World>-<YYYYMMDD-HHMMSS>[-label].zip`, local time. Same-second collisions bump the stamp by 1 s. Labels go through `CleanLabel` (letters, digits, `_`, `.`; everything else -> `-`, max 48 runes).
- Kind is the label: `auto` = automatic (the only kind ever pruned), `before-restore` = safety copy made by Restore (treated as manual, never pruned), anything else/empty = manual. Renaming an automatic backup makes it manual.
- Zip entries are relative to the world folder (no world prefix), dirs as `name/` entries so empty dirs (chunkdata/, metagrid/...) come back. Mode bits and mtimes kept. `.png/.jpg/.zip/.gz/.ogg/...` and empty files are Stored, everything else Deflate at `flate.BestSpeed` (level 1 is ~5x faster than default for ~same ratio on PZ .bin files). Every regular file is included: thumb.png, mods.txt, players.db/vehicles.db and their -journal files are all taken together because the game is not running (checked before and again after the zip is written; if it started in between the backup is discarded).

### Behaviour

- `Manager{SavesDir, Root, Running, FreeSpace, Now}`: everything injectable. `NewManager(cfg)` = real `~/Zomboid/Saves`, `play.IsRunning`, statfs / GetDiskFreeSpaceEx.
- Backup: running check -> walk (size, file count) -> free space >= uncompressed size + 200 B/entry + 32 MiB (conservative: zip is usually ~36 % of that) -> stream into `.<name>.zip.partial` in the same folder -> fsync -> rename. Cancel (ctx) or any error removes the partial. Progress: `Progress{Phase, Files, TotalFiles, Bytes, TotalBytes}`, throttled to ~10/s, phases `scan`, `backup`, `safety`, `restore`, `verify`.
- Restore: running check -> validate all entries before writing (rejects `..`, absolute, backslash, `:`, NUL, symlinks/non-regular, duplicates) -> free space in the mode folder -> safety backup `before-restore` of the current save (if it exists; failure aborts) -> extract into `<Mode>/.<World>.restore-*` (zip CRC checked by archive/zip at EOF, size per file) -> verify tree (entry count, types, sizes) -> running check -> `World` -> `World.old-<stamp>`, temp -> `World` (if that fails the old one is renamed back) -> remove `.old`. A failure to remove `.old` is only a warning (`RestoreResult.Warning`). Deleted saves restore the same way (mode folder created, no safety backup).
- Prune(mode, world, keep) deletes automatic backups beyond the newest `keep`; `PruneAll(cfg)` uses each save's keep.
- `ListAll` = saves from `play.Env.ListSaves` + every `<root>/<Mode>/<World>` folder; `Orphans()` (package func, default config) = backups whose save folder is gone. `SaveBackups.Save()` gives a `play.Save` (Dir set to where it would be) for the Play tab rows.
- Config `backups.json`: `{"root", "autoBeforeLaunch" (default true), "keepAuto" (default 5), "saves": {"Mode/World": {"auto", "keep"}}}`; per-save entries only store overrides of the defaults (`SetSave` drops entries equal to the defaults).

### Wiring into the Play tab (for the playtab owner / parent)

1. Before `play.Launch(play.SaveTarget(s))` for a save target, run `savebak.BeforeLaunch(ctx, s, progress)` (it returns nil at once when auto backup is off for that save; it returns `savebak.ErrGameRunning` if the game is up, `*savebak.NoSpaceError`, or ctx.Err() on cancel). Run it in a goroutine with a progress dialog; the GUI helper `u.runBakOp(title, func(ctx, pr) error { return savebak.BeforeLaunch(ctx, s, pr) }, func(err error) { if err == nil { launch } else { show error, offer "Launch without backup" } })` already does the dialog, cancel button and busy guard. Prune errors after a successful automatic backup are ignored so they never block a launch.
2. Save rows: add an expand toggle on the right of each save row (same `theme.MenuDropDownIcon()` low-importance button as the server rows). When expanded, show `u.saveDetails(save, onChange)` under the row (indent with `layout.NewCustomPaddedLayout(0, 0, 16, 0)` like server details). It is a plain VBox (no scroll of its own); its height changes when backups are added/removed, so `onChange` should re-measure: `list.SetItemHeight(i, rowTop.MinSize().Height + details.MinSize().Height)` and refresh the save list (a restore can bring a deleted save back). 4. The panel holds: summary (count, total size, deleted-save note), Prune automatic, open folder, settings (gear -> "Backup settings" dialog: root folder, default auto on/off, default keep, total of all backups, open root, prune all automatic), label entry + Back up now, "Back up before launching" check + keep N for this save, then one row per backup (thumbnail from the zip's thumb.png, date, label, size; Restore, Rename, Delete, Open folder).

### Hidden built-in browser (internal/webview)

The browser is never used for visible browsing. It runs hidden and does two things: keep a Steam session (sign-in) and press Steam's own Subscribe button in the background. Pages for people who want to look go to the default browser ("Open in default browser" buttons: per row icon, browse lists, Pack collection).

- Separate helper process: the launcher binary re-execs itself with `--webview` (intercepted in an `init()` in workshopbrowser.go before Fyne/flag parsing), plus `--ephemeral` when "Remember me" is off. The helper starts with no window and loads `webview.StatusURL` (`https://steamcommunity.com/app/108600/workshop/`) to learn the sign-in state. It is started when the Workshop outer tab is first selected (`ui.onTab`, hooked in `buildTabs`) or on the first Subscribe / Sign in. Closed with the launcher window (`ui.closers` in `SetOnClosed`) and on stdin EOF.
- Protocol = JSON lines. Launcher -> helper: `signin` {mode `qr`|`window`}, `cancelsignin`, `signout` (clears cookies/storage in the running profile; the launcher's Sign out restarts the helper instead, see below), `state`, `subscribe` {id, req, unsubscribe, deps}, `quit`; anything else is dropped (`Command.Valid`). Helper -> launcher: `ready`, `unavailable` (+error, exit 3), `external`, `session` {signed_in, name}, `qr` {image data URL, challenge}, `signinclosed`, `subresult` {id, req, result `done`|`already`|`not_signed_in`|`failed`, error}.
- Page script (`PageScript`, injected at document start into the top frame on every page): on DOMContentLoaded posts `{kind:"page", signedIn, name, item}`; signed in = `window.g_steamID` is a non-empty string (it is `false` logged out on community pages), name = text of `#account_pulldown`, item = the `id` of a filedetails page. On `/login` pages it polls every second for the QR (`findQR`) and posts `{kind:"qr", image, challenge}` when it changes.
- Helper core (`Helper`, engine-agnostic, unit-tested with a fake engine): emits `session` only when the state or name changes. Sign-in: `window` = load `LoginURL` (`/login/home/?goto=/app/108600/workshop/`) and show the small window (address bar visible); `qr` = same page hidden, QR forwarded. As soon as a page reports signed in during sign-in, the window is hidden and `session` is emitted. Closing the window (GTK `delete-event` / `WM_CLOSE`) hides it and emits `signinclosed` (the helper keeps running).
- Background subscribe: jobs are a FIFO, one at a time, paused while a sign-in is in progress (a running job is re-queued when sign-in starts). A job loads `ItemURL(id)`; when that page reports itself (`item == id`) the helper evaluates `SubscribeScript`: not signed in -> `not_signed_in`; no `#SubscribeItemBtn` -> failed; `toggled` class already in the wanted state -> `already`; else `click()` the button (Steam's `SubscribeItem` posts to /sharedfiles/subscribe or /unsubscribe and toggles the class) and poll every 300 ms: wanted state -> `done`; a `.newmodal` with both `.btn_green_steamui` and `.btn_blue_steamui` is Steam's "Additional Required Items" confirm -> green ("Subscribe to Just This Item", Steam's default; `deps` true would press blue "Subscribe to All"; the launcher always sends false); any other modal = Steam's error alert -> `failed` with its text; 15 s -> failed. Go-side timeout per job 30 s (`JobTimeout`). Logged-out item pages have no Subscribe button at all, hence the g_steamID check first.
- Launcher (`cmd/pzlauncher/workshopsession.go`, `wsSession`): request ids map to callbacks. `not_signed_in` keeps the request waiting and opens the sign-in dialog once; on `session` signed in all waiting requests are re-sent; cancelling sign-in fails them ("sign-in cancelled"). Rows: Subscribe / Unsubscribe (state from the list data, overridden by results in `wsBrowser.subState`), "Working..." while busy, status line above the hint. Pack collection "Subscribe to missing" = `webview.SubQueue` over missing, not subscribed items, one request at a time, progress "Subscribing 3 of 7: title...", Stop finishes the current item then stops, summary with failures and reasons.
- Sign-in dialog: "Sign in with the Steam Mobile app (QR code)" (hidden helper; Fyne dialog shows the QR on a 300 px white quiet zone, pixel scaling, replaced whenever Steam rotates it, closes by itself on sign-in; "Use Steam's login page instead"), "Sign in with Steam's login page" (helper window), "Remember me" checkbox (Fyne preference `workshop.rememberSignIn`, default off). Label: "Signed in as NAME (remembered)" / "(this session only)" / "Not signed in to Steam.".
- QR extraction (verified 2026-11-19 against the real login page in the hidden helper, `TestRealHelper`): Steam's React login page renders the QR as a square `<img>` with a `data:image/gif;base64` src, 41x41 px, one pixel per module, no quiet zone (class names are hashed, so it is found by shape: square data-URL image 21..1024 px; a square canvas is the second choice). The challenge URL (`https://s.team/q/1/<id>`) is read from the React fiber props of that img (`__reactFiber*` -> `memoizedProps` up 20 levels); hooking fetch/XHR did not see it (protobuf). `webview.DecodeQR` accepts png/gif/jpeg data URLs of at least 21 px.
- No web approval for QR challenges: a plain GET of `https://s.team/q/1/<id>` (no cookies) redirects to `https://store.steampowered.com/about/qrlogin/1/<id>`, which is the generic "About Steam" page (install Steam / get the mobile app), no approve button. So there is no "sign in with your browser" option; the default browser cannot share cookies with the helper anyway.
- Remember me: off = ephemeral profile. Linux `webkit_website_data_manager_new_ephemeral()` and no cookie storage, nothing written under `<UserConfigDir>/PZLauncher/webview` (the real test checks the folder is not created). Windows: go-webview2 has no InPrivate option, so the helper uses a `os.MkdirTemp` data folder and removes it after the message loop ends (retries for 5 s while WebView2 processes let go; if they hold it longer the folder stays in %TEMP%). On = persistent profile in `<UserConfigDir>/PZLauncher/webview` (WebKit cookies in `cookies.sqlite`). Changing the checkbox to a different mode restarts the helper (`Controller.CloseWait`), and turning it off deletes `webview.DataDir()` and `CacheDir()`. Sign out restarts the helper and, for a remembered profile, deletes those folders first.
- `webview.Controller`: `Send(cmd)` starts the helper on demand (restarts it if it was closed after `ready`); helper exits before `ready` or reports `unavailable` -> fallback for the rest of the session, `OnFallback` once. Launcher fallback: one dialog, label "Built-in browser unavailable...", Subscribe opens the item page in the default browser ("press Subscribe there"); the collection queue stops after opening one page.
- Allowlist (`webview.Decide`), unchanged: https only, Steam page hosts, Steam CDN asset hosts, about/data/blob, reCAPTCHA paths. In the sign-in window, user-initiated non-Steam links go to the default browser, everything else non-Steam is blocked.
- Linux engine (`engine_linux.go`): no cgo, purego dlopens libglib/libgobject/libgtk-3/libwebkit2gtk-4.1 (4.0 fallback)/libjavascriptcoregtk. Window (only for sign-in): back / forward / reload, address entry with padlock icon, WebKitWebView. JS via `webkit_web_view_evaluate_javascript` (4.1) or `run_javascript` (4.0). Cookie policy ALWAYS (Steam's login sets cookies cross-site via transfer requests). Data clear = `webkit_website_data_manager_clear` (cookies, local/session storage, IndexedDB, caches). All engine calls run on the GTK thread through `Post` (queue + `g_idle_add`).
- Windows engine (`engine_windows.go`): go-webview2 `pkg/edge`, own Win32 window created hidden, shown only for sign-in, WM_CLOSE hides. Script messages via `window.chrome.webview.postMessage`, JS via `Chromium.Eval`, cookie clear via `CallDevToolsProtocolMethod` (vtable 36) `Network.clearBrowserCookies`. Raw vtable indices as before (Source 4, add_NavigationStarting 7, add_SourceChanged 11, add_FrameNavigationStarting 17, Reload 31, CanGoBack/Forward 38/39, GoBack/Forward 40/41, add_NewWindowRequested 44, add_DocumentTitleChanged 46, DocumentTitle 48; controller get_CoreWebView2 25). Only `GOOS=windows go vet`/build checked; never run on Windows.
- Other OSes: `runEngine` returns `ErrUnavailable` -> fallback.
- AppImage: the helper inherits the launcher's environment; if a bundled LD_LIBRARY_PATH ever shadows the system GTK/WebKit, the helper fails before `ready` and the fallback kicks in.
- Not tested for real (needs a Steam account): the signed-in state detection after an actual login, the Subscribe click / required-items dialog / error alert handling, the QR approval, sign-out. Docking the browser into the launcher window was tried and dropped on request (2026-11-19).

### Thumbnails

`workshopthumbs.go`: max 4 parallel downloads, in-memory LRU (600) + disk cache `<UserCacheDir>/PZLauncher/thumbs/<sha1(url)>` (PNG, downscaled to 128 px with `modlist.Downscale`). images.steamusercontent.com previews are requested with `?imw=128&imh=128&ima=fit&impolicy=Letterbox` so only small images are downloaded. Rows only take an image if they still show the same preview URL (list rows are recycled). A preview that is not http(s) is a local file (mod.info poster) and is loaded with `modlist.LoadImage`, no disk cache. A failed load is remembered for `thumbRetry` (1 min) so list refreshes do not refetch it every time. Images are stored as NRGBA (Steam's resized previews come back as JPEG; encoding the YCbCr image straight to PNG gave 16-bit PNGs). ## sandbox options (2026-11-21)

Mods > Sandbox options (cmd/pzlauncher/sandboxtab.go, internal/sandbox). Step 1 of the user's settings plan (user picked: presets + server first, saves read-only).
- `sandbox.ParseOptions`: `option Group.Key { type, min, max, default, numValues, page, translation, valueTranslation }` blocks, one-line or multi-line, `/* */` and `--` comments stripped; types boolean/integer/double/enum/string. `LoadMod` reads `<VersionDir|CommonDir>/media/sandbox-options.txt` and translations from `media/lua/shared/Translate/EN/` (`Sandbox_EN.txt` Lua-table style with `..` concatenation, `Sandbox.json`, `Sandbox_EN.json`). Names: label `Sandbox_<translation>` (fallback `Sandbox_<name>`, then the raw name), tooltip `..._tooltip`, page `Sandbox_<page>`, enum values `Sandbox_<valueTranslation>_option<N>`; `<LINE>`/`<br>` become newlines, other `<...>` tags dropped.
- Targets: `~/Zomboid/Sandbox Presets/*.cfg` (flat `Group.Key=value`, `#` comments) and `~/Zomboid/Server/*_SandboxVars.lua` (`SandboxVars = { Group = { Key = value, }, }`, strings quoted). Only the local Server folder; the remote pzserver is not touched. Saves: not supported (sandbox values are in the binary map_sand.bin).
- Writing (`File.Render/Save`): only changed values are rewritten in place; every other line, comment, order and the line ending style stay byte-identical (checked 2026-11-21 against the user's real New.cfg and servertest_SandboxVars.lua: no-change render identical, 0 invalid values among 697/717 present options of 735). Missing options are appended (cfg) or inserted before the group's `},` / as a new group before the final `}` (lua). Values are validated (`Option.Valid`: bool, integer/double within min/max, enum 1..numValues, single-line strings). Save: refused while the game runs, shows old -> new per option and asks, backup `<file>.bak-<stamp>`, write via .tmp + rename.
- Option names without a group (e.g. Better Auto Mechanics' `BAM_Server_MinSuccessChance`) are top-level keys: `Name=value` in the cfg, `Name = value,` directly inside `SandboxVars` in the lua (inserted before the final `}`). The cfg reader takes every `key=value` line, the lua reader depth-1 and depth-2 values.
- An out-of-range or malformed number blocks Save ("Fix before saving: ...") instead of silently keeping the last valid value typed (found in the live test: typing 5000 left 500 as the edit).
- Live test method (2026-11-21): X11 build via `fyne-cross linux` (the local X11 headers are missing, so `go build` without -tags wayland fails), run in `gamescope --backend headless -W 1280 -H 900`, find DISPLAY from /proc/<pid>/environ, drive with xdotool (clicks on tabs, list rows, checkboxes and entries work; popup-menu items, the scroll wheel and list keyboard moves do not register reliably), screenshot with `magick import -window <id>`. Stop it by killing the gamescope PID (not pkill -f, which matches your own shell), so the window size isn't saved. Save refuses while ANY Project Zomboid runs, including another session's headless test.
